# omp as a supported CLI

## Summary

Added omp (`@oh-my-pi/pi-coding-agent`, checked against 18.3.5) as the seventh CLI, built on the Pi adapter from `781c0ea`. `CliKind::runs_pi()` now covers omp; `pi.rs` takes the CLI kind where omp differs.

## Changes

- `cli.rs`: `CliKind::Omp`, tested line 18.3, `omp/18.3.5` version parsing.
- `pi.rs`: agent dir per kind, omp session folder names (home-relative `-project-app`), header after omp's `title` line, `yielded: false` and notices in events, Bun source excerpt and startup watchdog lines dropped from stderr, `omp models --json` parser, read-only tools `read,grep,glob`.
- `headless.rs`, `orchestrator.rs`: `--approval-mode` per permission mode, planner with `--approval-mode always-ask`.
- `models.rs`: omp model list accepted although omp exits with 1 after printing it.
- `monitor.rs`, `transcript.rs`, `session.rs`, `skills.rs`, `events.rs`, `waiting.rs`: outside sessions (`@oh-my-pi` checked before Pi), transcripts, Resume id, `~/.omp/agent/skills`.
- Frontend: kind, label, text mark, permission table column, install and headless commands, signal text, i18n, fixture and a CLIs page test. README and CHANGELOG.

## Decisions

- Ask me `always-ask`, Plan `--tools read,grep,glob` plus `always-ask`, Auto `write`, Bypass `yolo`. omp has no `ls` and its `find` needs a judge model, both rejected by `--tools`.
- No screen pattern for omp's approval dialog: it was not observed on a real screen.

## Verification

- `cargo test --lib`: 114 passed; `cargo clippy --lib --tests` and `cargo check --all-targets`: clean.
- `npx vitest run`: 204 passed; `npm run check`: 0 errors.
- Real omp 18.3.5 with empty stdin (no prompt sent): every mode's flags and both planner flag sets exit 0 with the session header; `omp models --json` prints the full list in 2 s and exits 1.

## Limitations

- No omp run that sends a prompt was made from OpenCompanion; interactive approval prompts are not detected as Waiting for you.
