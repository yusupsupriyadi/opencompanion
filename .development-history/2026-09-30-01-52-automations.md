# Scheduled automations

## Summary

Automations start a CLI session in a folder on a cron schedule (local time) while the app runs, the tray included. They have a sidebar item and screen on the desktop, and a tab, list and edit screen on the phone.

## Changes

- `src-tauri/src/automations.rs`: cron through `croner` 4, validation, 30 s scheduler tick (missed runs once, Late after 2 min, Skipped while the last session runs a CLI), Run now, list and detail.
- `src-tauri/src/db.rs`: `automations` and `automation_runs` tables (50 runs kept, deleted sessions read as null).
- `src-tauri/src/lib.rs`, `session.rs`, `companion.rs`: commands, `automations-changed` event and `automations` socket message, scheduler thread, phone endpoints.
- `src/routes/automations`, `src/lib/Automation*.svelte`, `ScheduleField.svelte`, `schedule.ts`, `OutcomeChip.svelte`: desktop screen and schedule form.
- `src/lib/SessionFields.svelte`, `PhoneSessionFields.svelte`: session fields shared by New session and the automation forms.
- `src/routes/m/automations`, `src/routes/m/+layout.svelte`, `phone.css`: phone tab and screens.
- `README.md`, `DESIGN.md`, spec and plan in `docs/superpowers/`.

## Decisions

- Scheduler in the backend, not the OS; nothing runs while the app is closed.
- Schedules stored as 5-field cron; the simple modes are written as cron in the UI.
