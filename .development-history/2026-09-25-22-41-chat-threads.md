# Chat history per conversation

## Summary

Owner asked for chat history "per session". Chat was one endless conversation; it is now a list of chats, each with its own messages, and the planner only sees the open chat (PRD FR-27).

## Changes

- `src-tauri/src/db.rs`: `chat_threads` table, `thread_id` on messages, `ChatThread`, `thread_title`; `chat` per thread, `chat_message` by id, create/list/touch/delete thread; `migrate_chat` turns an old single conversation into one thread.
- `src-tauri/src/lib.rs`: `chat_threads`, `chat_history(thread_id)`, `chat_send(thread_id?)` (no id starts a new chat named after the message), `chat_delete_thread` replaces the unused `chat_clear`.
- `src/routes/chat/+page.svelte`: "Chats" panel (New chat, list, loading/empty/error states), `/chat?id=`, Delete chat with a second press, "This chat is gone" state, pending answer stays with its chat, folded list below 720.
- `src/lib/api.ts`, `src/routes/chat/chat.test.ts`, `DispatchCard.test.ts` fixture, `air-spike.rs`, `docs/PRD.md` FR-27, `DESIGN.md` D3.

## Decisions

- `/chat` without an id opens a new chat; past chats are one click away in the list.
- One planner turn at a time across chats, so Send waits while another chat is answering.
- Deleting a chat never stops the sessions its cards started.

## Verification

- `cargo test`: all passed (3 new db tests: isolation, legacy migration, titles). `cargo clippy --all-targets`: 0 warnings.
- `bun run test`: 51 passed (7 new chat tests). `bun run check`: 0 errors, 0 warnings.
- Copy of the owner's database: 12 old messages in one thread, title from the first line, no message without a thread.

## Limitations

- Not clicked through in the running app (no smoke test was requested). Chats cannot be renamed.
