# Pi as a supported CLI

## Summary

Added Pi (`@earendil-works/pi-coding-agent`, checked against 0.87.1) as the sixth CLI, built on top of the CCS change. Pi-specific parsing lives in `src-tauri/src/pi.rs`; `CliKind::runs_pi()` marks the adapter so a Pi fork such as omp can reuse it.

## Changes

- `src-tauri/src/pi.rs`: JSON event parser, stderr errors, `--list-models` table, planner answer, session folder encoding and session file lookup.
- `cli.rs`, `proc.rs`: `CliKind::Pi`, `~/.pi/agent/bin` search dir, and the launcher shim `node "%~dp0pi-launcher.js"` started as `node <script>`.
- `headless.rs`, `session.rs`: `pi --mode json` with the prompt on stdin, `--session` for follow-ups and Resume, Plan as `--tools read,grep,find,ls`, stderr errors in the timeline, Resume id found from Pi's session files.
- `orchestrator.rs`, `models.rs`: Pi as Chat planner (`--no-session`, read-only tools or `--no-tools`), `--model` and `--thinking`.
- `monitor.rs`, `transcript.rs`, `skills.rs`, `waiting.rs`: outside sessions, transcripts, `~/.pi/agent/skills`.
- Frontend: CLI kind, label, text mark, install and headless commands, Pi column in the permission table, signal text, i18n, fixtures and a CLIs page test. README and CHANGELOG.

## Decisions

- Pi has no permission prompts, so Ask me, Auto and Bypass pass no flags; the UI says Pi never asks.
- Interactive prompts starting with `@` get a leading space, since Pi reads `@arg` as a file even after `--`.

## Verification

- `cargo test --lib`: 107 passed; `cargo clippy --lib --tests` and `cargo check --all-targets`: clean.
- `npx vitest run`: 203 passed; `npm run check`: 0 errors.
- Throwaway live tests against a local OpenAI-compatible stub with an isolated `PI_CODING_AGENT_DIR`: headless run wrote the file and parsed Started, Message, ToolCall, Done; planner answered with and without read tools; no-auth error surfaced.

## Limitations

- No real provider account on this machine; interactive PTY sessions and Resume are covered by argument unit tests only.
